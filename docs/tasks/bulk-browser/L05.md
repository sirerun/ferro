## Ordered implementation steps

1. Wrap the existing schema subset validator; do not add a second schema engine. Preflight size, nesting and unsupported keyword/reference checks before spending.
2. Validate final result separately from partial output. Return frozen validation failures with bounded details; never coerce invalid data into a valid result.
3. Use G01's exact supported subset and resource caps. A bad schema fails even when a supplied result happens to match supported fields.
4. Do not edit runner.go or schema.go. If an existing helper prevents required preflight behavior, report the exact needed signature to G02 instead of expanding file ownership.

## Finish and stop rules

Use the RUNBOOK handoff template. Mark ready-for-review only when the required behavioral tests and full owning-package tests pass and git diff --check passes. Do not claim installed/live verification. Commit only owned files on the assigned branch; do not merge, push, deploy or start another task unless instructed.
