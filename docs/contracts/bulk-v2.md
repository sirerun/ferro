# Ferro task contract v2 — contract revision 2

Status: local bounded read-only implementation contract, 2026-09-24. CONTRACT_SHA and acceptance/verification status are recorded in the dispatch ledger and foundation review evidence; each packet verifies the file lock before editing. This is not runtime or hosted qualification.

## Wire types and bounds

The request literal is `ferro.task/v2`; result literal is `ferro.result/v2`. `RunTaskV2Request` carries required `task_id`, `goal`, `model_profile`, `output_schema`, and `policy`; numeric overrides are pointers so an omitted value differs from explicit zero. All supplied numerical limits must be positive; zero is rejected. Optional `start_url` must have an allowed policy origin; `replay_key` is only a caller label. Goal is at most 16 KiB UTF-8 bytes, schema at most 32 KiB/depth 16, request at most 64 KiB. Task IDs are ASCII `[A-Za-z0-9_-]{1,128}`. Unknown request fields and trailing JSON are rejected. Evidence is `compact` or `artifacts`; omitted means compact.

Revision 2 clarifies the validation boundary without changing wire literals, limits or public signatures. `ValidateTaskRequestV2` enforces the 64 KiB limit on original JSON before decoding. Shared semantic validation checks and normalizes typed fields; receipt admission and canonical hashing reuse it without reapplying the original byte limit after defaults or Unicode origin normalization. Internal callers must validate original wire bytes before typed admission. An already-normalized struct cannot prove the length of its original encoding. See ADR 009.

Pilot ceilings: runtime 90,000 ms; actions 20; model requests 3; repairs 1; planning passes 2; output tokens 2,048; input tokens 12,000; total reserved tokens 24,000. Overrides only tighten the service-configured value. A monetary reserve cannot be implemented without a verified rate input. The initial L03 constructor has none, so it rejects every nonnil reserve with ErrUnsupportedCostReserveV2. Hard-dollar mode is rejected with ErrUnsupportedHardDollarV2. Actual reported costs remain nullable and are retained independently.

Policy permits only `read_only` and exact HTTP(S) origins. Credentials, wildcards, query, fragment, and non-root paths are rejected. Hosts are lowercase, trailing DNS dot removed, default ports removed, origins deduplicated and sorted. Service allowlist intersection is deferred to G02. Navigation, snapshot, extraction, scroll, wait and settle are allowed by the L04 wrapper; click, fill, select and key are denied.

Output schema keywords are the existing subset: `$schema`, `title`, `description`, `type`, `properties`, `items`, `required`, `additionalProperties`, `enum`, `minimum`, `maximum`, `minLength`, `maxLength`, `minItems`, `maxItems`. No remote refs. The existing validator remains authoritative for matching and type semantics. Bounds: summary 2 KiB; inline output 16 KiB; artifact and receipt 4 MiB; artifact read chunk 64 KiB; provider body 2 MiB/error body 8 KiB; storage 256 MiB. No automatic eviction. Cleanup only reconciled terminal receipts older than 30 days and leaves key tombstones; exhaustion fails closed.

## Accounting and identity

Nullable usage fields distinguish unknown from zero. Transmission is `not_sent`, `sent_unknown`, or `response_received`. Metadata completion contract is one HTTP request per invocation and no fallback retry; legacy `LLMClient` and `run_task` remain unchanged. Request kinds are planning, repair, extraction, and parse_retry; every attempt counts, with planning and repair ceilings separately enforced by L03. Unknown usage keeps the reservation; reconciliation is once-only. No inferred billed usage from text length.

Replay identity canonicalizes the string-field context (principal, profile revision, model, policy/schema digest, compatibility, layout, caller label) as JSON and hashes SHA-256 hex. Empty required partition values fail closed. Receipt owner is trusted server identity, never a request field. Atomic owner/task admission returns existing state for same digest and conflict for changed digest. Restarted in-flight work is outcome_uncertain and is never redispatched automatically.

## Profile and result contracts

Profiles are immutable revisions from a content digest; endpoint and exact model are service resolved, credentials are references and never serialized. HTTPS is required except localhost HTTP for private profiles. No automatic fallback. Legacy mappings use explicit configured values named `legacy-mcp` and `legacy-chat`.

The result status enum is succeeded, failed, blocked, cancelled, budget_exhausted, outcome_uncertain. Error categories are invalid_input, profile_missing, disconnected, pairing_changed, tab_busy, origin_denied, login_required, output_invalid, provider_error, deadline_exceeded, capability_unsupported, storage_error and request_conflict. Stage is a bounded diagnostic chosen by the integrator; retry is never, reconcile_only, or known_not_executed. Unknown effects allow only never/reconcile_only. Malformed input/authentication fail before admission through MCP errors; admitted failures retain a structured result and receipt. Budget exhaustion uses status budget_exhausted and category deadline_exceeded for runtime expiry or capability_unsupported for an unavailable cost guarantee; count exhaustion has no required error object, with the summary naming the exhausted counter. No category may suggest that uncertain work is safe to retry.

Success has validation valid and exactly one accepted-output location: inline Result or ResultArtifactID referencing an application/json artifact. Artifact-only success is allowed only for output larger than 16 KiB and within 4 MiB. The result builder must validate the actual output before storing it; envelope validation cannot establish the contents of external bytes. Failure contains neither accepted-output form; PartialResult remains separate. Profile revision, effective limits, timestamps, usage and budget appear in all terminal envelopes. All numeric usage is nonnegative; absent is unknown, explicit zero stays zero. Cost and execution outcome remain independent.

## Resolved seams and compatibility

- core.ValidateSchemaShapeV2 performs bounded preflight and calls the existing private checkSchema. MCP calls that exported contract helper. L05 PreflightSchemaV2 delegates to it, and ValidateResultV2 combines it with existing validateSchema; no second schema engine.
- TaskPolicyGuardV2.Check must check captured transient lease/pairing generation and current service authority before and after each allowed browser operation. It is supplied by G02 from trusted owner state, not request fields. The wrapper separately verifies snapshot URL against canonical policy origins, with guards around the internal snapshot. Internal origin snapshots do not consume an extra action; denied input calls never dispatch. Navigation prechecks its target and verifies the observed origin afterward. This is automation authority, not network egress confinement.
- Legacy LLMClient, run_task and direct tools retain their existing behavior. Metadata-only provider calls are separate from legacy schema fallback. See [provider usage mapping](provider-usage-notes.md) for the dated official source and parsing decisions.
- Generic MCP clients, including external orchestrators, use the same task/receipt tools. No consumer-specific imports, fields, branches or scheduler belong in Ferro. Hosted adoption reuses behavioral contracts but must supply account authority, tenant storage and fencing; local receipts do not establish hosted isolation. Governed direct-action mutation receipts require a separately accepted extension and do not gate these read-only packets.

## Packet-specific executable decisions

### L01 profiles

Add NewLegacyProfileV2(name, endpoint, model, credentialRef string, limits core.LimitsV2) (ProfileV2, error) and DescribeProfileV2(profile ProfileV2) ProfileDescriptionV2 in the L01-owned file. Legacy name is exactly legacy-mcp or legacy-chat; values come from explicit existing settings, never automatic selection. Profile revision is lowercase SHA-256 hex over encoding/json.Marshal of ProfileV2 with Revision empty, normalized endpoint and fully materialized limits. Resolver computes/verifies that revision before credential lookup; a different body under an existing revision fails. Unknown/invalid source profiles never trigger credential lookup. Copy all reference-valued fields before returning. Resolver errors must not echo credential values or arbitrary source errors. Profiles permit HTTPS or HTTP with localhost/loopback literal hosts only; reject userinfo, query and fragment. Public descriptions contain names/revisions and read_only capability, never endpoint or credential ref/value. No changes to config loading/chat routes until G02.

### L02 provider metadata

CompleteWithUsage does one non-streaming HTTP attempt using the same configured endpoint/model/timeout/max-token semantics as the existing client, without retries or redirects (a redirect would be an unadmitted extra HTTP request). Keep legacy Complete/CompleteSchema compatibility. Add UsageCostCurrency string to OpenAICompatible; only explicit USD allows usage.cost conversion to billed micro-USD. Empty disables monetary parsing while preserving token parsing; other values fail before dispatch. This is server-controlled profile wiring, never an arbitrary caller option. Retain returned usage even when content/choice validation fails. Bound body reads with limit+1 and reject excess; redact provider error bodies from diagnostics. Transmission not_sent is only for pre-HTTP construction/configuration failures; every error after client.Do starts is conservatively sent_unknown until a response is observed.

### L03 budgets

NewTaskBudgetV2 accepts positive LimitsV2 and a nonzero started timestamp no later than now. Store a fixed deadline; no timer goroutines. Validate context/deadline on every admission. Request kinds: planning, repair, extraction, parse_retry. Charge every request attempt and kind ceiling before dispatch. Input may be zero; output reservation must be positive; both must be within configured per-call limits. Check arithmetic before addition. Unique reservations reconcile at most once; malformed usage/transmission returns an error without mutating accounting or marking it reconciled. not_sent may release its token reserve but cannot erase the attempted-call count. Known total usage replaces its outstanding token reserve; if only input/output are present sum them safely. If actual usage exceeds the estimate, retain the truthful overrun and reject later admissions. Unknown usage retains its token reserve and increments UncertainRequests. ReportedUsage sums only explicitly reported fields (known subtotal); nil means no value was reported, and UncertainRequests prevents treating the subtotal as complete. ReservedTokens is cumulative actual-or-reserved charge, not only current in-flight tokens. Estimates and maximum output reservations remain separate cumulative counters. Monetary reserves and hard-dollar mode are unsupported as above. Snapshot returns deep copies. Private injected clock is permitted for deterministic deadline tests; no sleep-based tests.

### L04–L10 seams

L04 must reject nil driver/guard/budget and unsupported policy at construction; no unchecked fallback driver. L05 rejects unsupported schemas before model work and never silently changes existing schema semantics. L06 uses encoding/json.Marshal of ReplayContextV2 (stable struct field order) followed by SHA-256 lowercase hex; all nine fields are required for replay, and no final page facts are cached. CallerLabel empty means no replay requested, return empty key without error; other missing fields return empty key and an error. PolicyDigest inputs use sorted canonical origins and mode; schema digest is over compact canonical JSON, not incidental whitespace.

L07 OpenReceiptStoreV2 is a single-process store with an exclusive OS lock; a second opener fails rather than overwriting state. No external dependency. Store key admission, receipt transition and artifact references atomically/durably; reject malformed digest/key/owner before allocating. Permanent bounded tombstones preserve expired key identities, returning ErrReceiptExpiredV2 on repeat admission; capacity exhaustion fails closed. Do not trust requestDigest blindly: compute canonical request JSON digest within Admit and compare. Caller identity is a trusted nonempty principal supplied by G02, not the MCP session nonce. Return copies; do not leak data through owner-mismatch errors. Finalize must preserve task/execution identity and validate the envelope. Unknown side effects or unknown spend remain unreconciled and ineligible for cleanup. Results, readback and cleanup after Close must fail. ReadArtifact argument order: ctx, owner, executionID, artifactID, offset, length.

L08 copies safe ExecutionRecordV2 fields, validates original JSON/schema result state before promoting it (record Validation is trusted only from G02's actual schema check), writes oversized accepted output through the injected sink, and emits ResultArtifactID after checking returned digest/size against bytes. It must fail on sink error; it is not a pure function when storing artifacts. Bound/truncate summaries on UTF-8 boundaries without altering accepted JSON. L09/L10 use actual frozen Go validators via check_bulk_v2.py; fixture-based evidence remains separate from a live browser qualification.
